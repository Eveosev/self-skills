# 论文 Figure 在 Obsidian 中的布局

## 核对来源

以同一版本 PDF 为依据，逐个记录原 Figure 编号、所在页、共享图注、子图标签和
位置。可参考 MinerU 的 `*_content_list.json` / `*_middle.json` 中的页面与边界框，
但应查看 PDF 页面确认：一个 Figure 可能被拆成多张图片，也可能跨多个提取块。
`figure-003.jpg` 是资产编号，不一定是论文的 Figure 3；不能依据编号或宽高猜布局。

## 优先保留完整 Figure

1. 查看提取图片。若已经含全部面板、坐标轴、图例及子图标签，直接引用。
2. 若被拆分，从 PDF 按核实后的区域整体裁剪，建议渲染分辨率 200–300 DPI；
   保留原行列位置和面板之间的留白。不按统一格子强行重排原图。
3. 裁剪图写入 `assets/<slug>/`，使用明确名称如 `paper-figure-04.png`；
   确认文件存在后追加到 `bundle.image_files`，保留原提取图片及其清单条目。
4. 保存 `figure-layout.json` 并在 bundle 中登记 `figure_layout_path`；至少记录
   Figure 编号、PDF 页码（从 1 开始）、原子图文件、实际使用图片、图注与行列位置。
   若保存裁剪边界框，同时注明坐标单位和原点。保留 PDF 路径为 `bundle.pdf_path`。

```markdown
![Figure 4：Prefill 和 Decode 的吞吐与算术强度](../../assets/<slug>/paper-figure-04.png)

*Figure 4：上排为吞吐，下排为算术强度；左列为 Prefill，右列为 Decode。*
```

图注放在图片下方，保留原编号；可用中文概括，但不能改变原文比较对象、条件和
结论。裁剪时若包含原始图注，也仍可补充中文说明。

## 独立子图的 Markdown 兼容写法

无法获得完整裁剪图，但已确认子图布局时，用标准 Markdown 表格。
以下 `<slug>` 和文件名仅为示意；真实笔记必须替换为已登记的资产。

1×2（一行两列）：

```markdown
| (a) | (b) |
| :---: | :---: |
| ![(a)](../../assets/<slug>/a.png) | ![(b)](../../assets/<slug>/b.png) |

*Figure N：共享图注。*
```

2×2（两行两列）：

```markdown
| 左列 | 右列 |
| :---: | :---: |
| ![(a)](../../assets/<slug>/a.png) | ![(b)](../../assets/<slug>/b.png) |
| ![(c)](../../assets/<slug>/c.png) | ![(d)](../../assets/<slug>/d.png) |

*Figure N：(a)…；(b)…；(c)…；(d)…。*
```

2×3 同理扩成三列和两行。实际顺序必须依原图，不默认标签一定按行排序。
表头按原图含义命名；没有合适的文字时可使用空表头。
表格内描述中的 `|` 要写为 `\|`。保持表格连续，行间不插空行。
使用标准图片链接，无需 HTML、CSS 或 Obsidian 插件；不要使用固定像素尺寸，
以便主题自适应。窄屏表格可读性有限，需要精确排版时仍优先整图。

## 完成检查

- 对照 PDF：每个面板的位置、标签、坐标轴和图例均保留；不同 Figure 不混排。
- 对照笔记：同一 Figure 共用图注，编号正确，没有完整图与子图重复插入。
- 对照资产：图片链接均能解析，实际使用文件已在 bundle 清单登记。
- 实际查看裁剪图；若无法取得原版面，注明“原始子图布局未核实”，不声称已恢复。
